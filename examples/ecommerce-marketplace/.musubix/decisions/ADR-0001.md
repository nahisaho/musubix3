# ADR-0001: Polyglot microservice boundaries for the marketplace example

## Context / 背景
The article must demonstrate MUSUBIX3 tracing requirements, design, code, and
tests across a realistic large-scale, multi-language system, not a single
TypeScript project.

## Decision / 決定
Split the order-creation flow into five backend services plus one storefront
rendering unit, each in the language best suited to its role and to the
toolchains actually available in the experiment environment (go, cargo,
javac/mvn, python3, node):
inventory reservation (Go), risk scoring (Rust), order orchestration (Java),
recommendation (Python), BFF (TypeScript/Node.js), and storefront rendering
(TypeScript/Next.js conventions). Cross-service calls use plain HTTP; the order
service calls inventory and risk directly, and the BFF calls the order service.

## Consequences / 結果
Each service keeps its own dependency manifest, native test runner, and
trace annotations, so `graph index` and `trace check` must resolve imports and
requirement links independently per language. Full container orchestration
(docker-compose) and CI/CD are documented as integration/definition artifacts;
this experiment does not claim to have executed them end-to-end.
