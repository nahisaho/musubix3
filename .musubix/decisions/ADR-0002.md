# ADR-0002: Artifact-bound staged human approvals

## Context
Validator success proves machine-readable consistency but not human agreement. Approval must become stale when the reviewed material changes, while generated gate evidence must not create circular hashes.

## Decision
Store schema-v1 approval evidence under `.musubix/evidence/approvals/<stage>.json`. `approval prepare` exposes the exact deterministic manifest/hash for review, and recording recomputes and rejects any mismatch. Bind requirements approval to requirements and constitution files, design approval to requirements/design/ADR/constitution files, and release approval to all project inputs returned by the deterministic file inventory, excluding only recognized generated evidence/log locations. Require the requirements stage before design and both earlier stages before release. Release recording recomputes the shared gate and requires every required non-approval check to pass instead of trusting mutable cached `quality.json`.

Local approval is explicitly self-reported. Independent identity and authorization remain the responsibility of protected review, CODEOWNERS, CI/OIDC, or equivalent repository controls.

## Rejected alternatives
- Treat validator success as approval: no human decision exists.
- Store an unbound boolean: artifact changes would retain stale approval.
- Bind release approval directly to `quality.json`: rerunning the final gate would invalidate the approval through a generated timestamp.
- Add a second agent or approval service: conflicts with the native Copilot-only architecture.

## Consequences
Approval is deterministic and locally verifiable, but local approver identity is not cryptographically authenticated. Release workflows needing strong identity must combine it with protected review or attestation.
