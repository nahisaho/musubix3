# ADR-0017: Recognize an explicit "none — <reason>" marker as a valid ADR exemption

## Context

`validateDesign()` (`packages/domain/src/design.ts`) requires every `DES-*`
component to reference at least one ADR via its `ADRs:` field (`DES_ADR`).
Some components genuinely have no architecturally significant decision (a
thin pass-through that only delegates to an already-decided component), and
today the only way to satisfy validation is to fabricate a low-value ADR,
which pollutes the decision log instead of improving traceability (GitHub
Issue #5). Writing `ADRs: none` is rejected identically to omitting the
field, so authors have no lightweight, explicit way to record and justify a
genuine exemption; a reviewer cannot distinguish "author forgot" from
"author decided no ADR applies" by reading the design document alone.

## Decision

- Recognize a literal `none` value (case-insensitive) in a component's
  `ADRs` field, followed by a hyphen/en dash/em dash/colon separator and a
  free-text reason, as an explicit exemption marker: `ADRs: none — <reason>`.
- Require the reason to be non-empty and not a placeholder (`TODO`, `TBD`,
  `N/A`, `未定`); a bare `none` or `none — TBD` still fails validation with a
  new diagnostic (`DES_ADR_EXEMPTION_REASON`) distinct from `DES_ADR`, so the
  author sees "you need to justify the exemption" rather than "you need an
  ADR", and a genuinely blank/omitted field still fails as `DES_ADR` exactly
  as before.
- Detect the marker from the same raw field text already captured by the
  existing `field()` helper, alongside (not instead of) the existing
  `references(..., 'ADR')` call used to populate `Component.decisions`. If
  the field also contains a real `ADR-*` reference, the exemption marker is
  ignored and the field is validated exactly as it is today — an author
  cannot mix a real ADR reference with a "none" exemption in the same field.
- The exemption is per-component and requires an explicit reason each time;
  there is no global "skip ADR checking" switch and no way to exempt a
  component silently.

## Rejected alternatives

- **A separate `ADR-Exempt: <reason>` field.** Rejected: adds a new markdown
  field name that every design template, doc-comment example and adapter
  must learn, for the same information a "none" value in the existing
  `ADRs` field already conveys; more surface area for the same behavior.
- **A reserved `ADR-0000` sentinel ADR that components reference to mean
  "no ADR applies."** Rejected: `ADR-0000` would need to exist as a real
  file for `context.adrIds` validation to accept the reference, or the
  validator would need a special-cased ID outside the normal ADR namespace;
  either way it looks like a real decision record was made when none was,
  which is misleading to a reader browsing `.musubix/decisions/`.

## Consequences

- Authors can express "no ADR needed, and here is why" directly in the
  `ADRs` field without inventing a placeholder ADR, and every exemption
  carries a human-readable justification a reviewer can check.
- `design validate` gains one new failure mode (`DES_ADR_EXEMPTION_REASON`)
  but does not regress `DES_ADR` for an empty field or `DES_ADR_LINK` for an
  unknown ADR reference.
