# ADR-0041: Persist canonical workflow reconciliation and migrate waivers with a recoverable workflow-first commit

## Context

Workflow declarations outlive individual Copilot CLI sessions, but current
verification replaces its invocation list with only the supplied transcript
set. Reconciliation therefore regresses after resume unless every historical
transcript is supplied again. Existing workflow waiver snapshots also include
the global verification head, so an unrelated transcript hash invalidates every
waiver. Approximately two thousand version-1 records already exist and cannot
be rewritten or silently discarded.

The solution must remain fail-closed, preserve strict transcript guarantees,
work under the existing evidence writer lock, keep legacy workflow documents
readable, and tolerate interruption between workflow and waiver evidence
writes.

## Decision

Persist a closed, canonical `reconciliation` object inside
`.musubix/evidence/workflow.json`. Its ledger is keyed by `toolCallId`,
separates semantic invocation fields from provenance sources, supports only the
commutative incomplete-to-terminal promotion, and stores deterministic
declaration bindings plus their digests. Persist the effective verification
mode, optional strict session constraint, and declaration skew used to compute
bindings. Persisted strict ledger mode is sticky, while only a configured
session constraint is persisted; per-run session assertions remain provenance
and can change across strict sessions. A newly configured constraint tightens
an anchor-less ledger on the next successful persisting verification; once
present, the anchor remains sticky if config later omits it. Confirmed ledger
reset is the only mode relaxation or configured-anchor replacement path.
Compatible file provenance uses each producing file's byte hash so re-verifying
that file in another file set does not multiply sources.
`verification.invocations` remains only the current-run transcript projection.

Use scope-local version-2 waiver snapshots based on the declaration, its
recomputed binding, and same-skill semantic invocation prefix. Keep version-1
evaluation for legacy workflows. During migration, preserve historical records
and append deterministic version-2 successors that retain approval identity and
time. Build reusable per-skill candidate indexes and memoize event-index scope
heads for each validation or migration pass so historical waiver volume does
not multiply complete-ledger scans.

Commit workflow evidence first with the existing same-file atomic replacement,
then append waiver successors. Select authoritative, validly linked version-1
records whose next-state reason is identical or resolved regardless of legacy
global-head staleness. Compute migration reasons and successor hashes from the
just-written reconciliation values plus configured read-side mismatch rules;
raw per-run options affect them only through values persisted into that next
state. When a waiver append is unsafe, fails, or is interrupted,
recompute that same bounded pending set and retry idempotently on a later
successful verification. Include reconciliation digest fields in
`workflowEvidenceHead`.
Unsafe waiver shape/chain data leaves the committed workflow usable and returns
the distinct non-persisted `WORKFLOW_WAIVER_MIGRATION_SKIPPED` warning; an
actual second-file write failure remains nonzero
`WORKFLOW_WAIVER_MIGRATION_WRITE_FAILED`.

## Rejected alternatives

- **Replace verification with the newest transcript and require operators to
  re-supply every historical file.** Rejected because it is the defect being
  corrected and cannot reconcile unavailable completed sessions.
- **Treat SAT/hash consistency as behavioral proof.** Rejected because hashes
  prove canonical evidence identity, not that invocation behavior occurred;
  transcript lifecycle validation and declaration diagnostics remain required.
- **Rewrite all version-1 waiver records in place.** Rejected because it would
  destroy the append-only audit chain and human approval provenance.
- **Use a generic two-file transaction journal for workflow and waiver files.**
  Rejected because a safely committed workflow document is independently valid
  and the second append is deterministically recoverable by recomputing
  authoritative linked version-1 scopes. A new journal/recovery command would
  add broader failure states and duplicate existing transaction machinery
  without improving fail-closed behavior.
- **Ignore compatible provenance in strict mode.** Accepted only as candidate
  exclusion: strict bindings require strict sources, while compatible sources
  remain useful when reconciliation mode is compatible.
- **Allow unbounded durable provenance.** Rejected because every gate/status
  read canonicalizes and validates the evidence. Dedicated reconciliation
  limits and an explicit confirmed reset path bound cost and provide recovery.

## Consequences

- Resumed verification is order-independent and no longer needs historical
  transcript files after their semantic invocations enter the ledger.
- Strict configuration cannot be satisfied by compatible-only provenance.
- Unrelated transcript/session hashes no longer stale declaration-local
  waivers, while relevant invocation/binding changes still do.
- An interruption after the workflow write may leave migration pending, but
  never produces a success-shaped waiver or requires repeated approval; the
  next persisting verification retries it.
- Operators gain a destructive, confirmed ledger-only reset for limit or
  corruption recovery and must re-supply sufficient transcript evidence.
- Attestations change whenever authoritative reconciliation digests change.
- Rescue migration cannot distinguish unrelated legacy global-head staleness
  from an out-of-band declaration edit; valid linkage and an identical or
  resolved next-state reason are the explicit bounded trust criteria.
