# ADR-0035: Pin the smallest reviewed Node.js 24 action majors with an offline lock

## Status
Accepted

## Context
All external JavaScript actions pinned by the three repository workflows declare
the Node.js 20 action runtime. GitHub-hosted runners currently force those
actions onto Node.js 24 and emit a deprecation warning. Updating directly to
each action's newest major would combine the runtime migration with unrelated
behavior changes and increase release-path risk.

Immutable SHAs alone do not explain which release tag, runtime declaration, or
major migration was reviewed. Conversely, resolving tags or downloading
`action.yml` during ordinary tests would make the quality gate network-dependent
and non-deterministic.

## Decision
Select the latest reviewed release within the smallest major that has a
compatible release whose pinned `action.yml` declares `runs.using: node24`:

- `actions/checkout` v5.1.0
- `actions/setup-node` v5.0.0
- `actions/setup-python` v6.3.0
- `actions/setup-go` v6.5.0
- `actions/setup-java` v5.7.0
- `actions/upload-artifact` v6.0.0
- `actions/download-artifact` v7.0.0

The runtime field is copied from `action.yml` at the exact pinned SHA, never
from release-note prose. In particular, setup-go v6.0.0 and v6.1.0,
upload-artifact v5.0.0, and download-artifact v6.0.0 still declared Node.js 20
despite release notes claiming Node.js 24 support, so they are ineligible.

Pin exact reviewed release commits, not moving major tags. Record every external
action in `scripts/github-actions-lock.json`, including the exact SHA and tag,
action kind, observed runtime, immutable source, reviewer and date, every
crossed major paired with its immutable migration source. The source URL for
runtime evidence embeds the exact commit SHA. Workflow comments use the full
reviewed release tag, not a major-only label. Ordinary tests validate the
workflow-to-lock relationship offline.

Protect existing workflow structure and security behavior with a checked-in
fixture derived from commit
`7f1f45297a5bef4413257c42071c12fba91cc9e8`. The requirements and CHANGE record
the source blob IDs and SHA-256 correspondence so the fixture's origin is
reviewable even when CI uses a shallow checkout. Artifact tests compare resolved
downloaded file locations, not raw upload/download path strings.

Keep GitHub-maintained floating hosted-runner labels. Document their intentional
use and require compatibility validation when GitHub changes the backing images.
Require the first post-merge CI log to contain no forced Node.js 20 action
warning; record equivalent release and npm-publish evidence at the next real
publication rather than triggering a release only for this migration.

## Rejected alternatives
- **Set `ACTIONS_ALLOW_USE_UNSECURE_NODE_VERSION`.** This suppresses migration
  pressure while retaining deprecated action runtimes.
- **Update only setup-node.** The observed npm-publish run names setup-node, but
  every other pinned JavaScript action also declares Node.js 20 and would remain
  deprecated in workflows that execute it.
- **Update every action to its newest major.** This crosses additional majors
  unrelated to Node.js 24 and unnecessarily expands behavioral risk.
- **Use moving `@vN` references.** Mutable references weaken supply-chain
  review and violate the repository's immutable-pin convention.
- **Fetch action metadata during tests.** Network-dependent verification is not
  deterministic and cannot guarantee repeatable local or CI results.
- **Pin Ubuntu to a dated image.** A fixed image postpones rather than removes
  maintenance and would reduce the intended hosted-runner compatibility signal.

## Consequences
- Action runtime and reviewed migration metadata become explicit, auditable
  repository inputs.
- setup-node v5 can automatically enable package-manager caching when a root
  `packageManager` field exists; tests protect the repository's current omission
  of that field, and the npm-publish job has no checked-out package manifest.
- setup-go v6 changes toolchain-selection behavior; the existing explicit
  `go-version: '1.22'` input remains protected and adapter/release validation
  confirms the selected toolchain remains compatible.
- The migrated Node.js 24 action releases require hosted runner 2.327.1 or
  newer. GitHub-hosted floating labels satisfy that dependency; self-hosted
  runners are outside these workflows.
- download-artifact's artifact-ID extraction change does not affect this
  repository because every download selects an explicit artifact `name`;
  resolved destination paths remain contract-tested.
- Updating an action later requires updating both the SHA/comment and its lock
  record, including any newly crossed major migration sources.
- The lock proves consistency with reviewed metadata, not the current state of
  upstream repositories; immutable source URLs and human review remain part of
  the trust boundary.
- Artifact action major changes receive focused static path-contract coverage,
  while a real release remains the final operational confirmation.
- Future hosted-image changes intentionally require renewed compatibility
  validation rather than silently inheriting a fixed runner image.
