# ADR-0038: Set the required full-test gate timeout from observed gate duration

## Context

The complete required Vitest suite initially passed in 177.28 seconds while the
gate allowed 180 seconds, and two later release-gate runs timed out. After
raising the ceiling to 240 seconds, `command:test` took 225.40 seconds within
the final unscoped gate run, leaving only 14.60 seconds. The timeout is an
execution ceiling rather than correctness evidence, but both observed margins
are operationally unstable.

## Decision

Set only the `.musubix/config.json` command named `test` to
`timeoutMs: 305000`. This is the latest observed 225.40-second `command:test`
duration within an unscoped gate run multiplied by approximately 1.35 and
rounded up, leaving 79.60 seconds of margin. Preserve
the command, arguments, required status, selected tests, worker bounds,
constitution limits, other command timeouts, and policy baseline.

## Rejected alternatives

- Keep 180 seconds: rejected because two consecutive gate executions timed out.
- Keep 240 seconds: rejected because the latest 225.40-second run consumed
  93.9% of the ceiling and contradicted the reviewed margin.
- Reduce or shard the required suite: rejected because it changes coverage and
  is not necessary for this configuration defect.
- Use a dynamic wall-clock ratio: rejected because elapsed duration is
  environment-dependent and is not deterministic correctness evidence.
- Increase every command timeout: rejected because only the full-test command
  demonstrated insufficient margin.

## Consequences

Release gates allow the complete suite up to 305 seconds without weakening any
required check. Future suite growth must be reviewed against this explicit
ceiling; passing within the timeout does not itself prove test correctness.
