# ADR-0015: Recognize language-specific token syntax at the exact boundary that misreads it, without weakening other adapters or commands

## Context

Two independent regexes in `packages/analysis/src/` misread language-specific
syntax they were never designed to recognize. `idOf()`
(`adapters.ts`) requires a word-boundary (`\b`) immediately after a test
ID's trailing digit run; Go and Rust identifiers cannot contain any
non-word character, so a descriptive suffix directly after the digits (as
in `TEST_LOGI_005AssignsMinimalDistanceVehicle`) can never satisfy that
boundary, forcing an artificial, non-descriptive naming convention
(GitHub Issue #9). Separately, `configLint()`'s `looksLikeRepoRelativePath()`
flags any argument containing `/` that does not exist as a file, which
misreads Go's `./...` recursive package-pattern wildcard as a missing path
(GitHub Issue #7).

## Decision

- Change `idOf()`'s trailing anchor from `\b` to a negative lookahead
  `(?![0-9])` — the digit run remains a greedy quantifier, so a longer
  numeric ID (e.g. `0051`) is still matched in full, while a following
  non-digit character (letter, underscore, dash, or end of string) no
  longer blocks recognition. This applies uniformly to every adapter that
  calls `idOf()` (vitest/jest/pytest/go-test/cargo/junit/dotnet/php), since
  the boundary was already permissive enough for adapters whose reports
  contain free-form title text; only Go/Rust identifiers were affected by
  requiring a non-word character specifically.
- Add `isGoPackagePattern()`, matching Go's `./...`/`pkg/...` recursive
  wildcard syntax, and skip `CONFIG_ORPHANED_PATH` for an argument matching
  it only when the owning command's configured `adapter` is `go-test`. Every
  other command's path-like arguments are checked exactly as before.

## Rejected alternatives

- **Drop the trailing anchor entirely (match any following character).**
  Rejected: this reopens exactly the regression case ADR review flagged —
  `\d{3,}` could then be perceived as ambiguous when a real ID is
  immediately followed by more digits from an unrelated number, though the
  quantifier's greediness already prevents this if kept. Using an explicit
  `(?![0-9])` documents the actual intended guarantee (never split a
  contiguous digit run) rather than relying on quantifier greediness alone
  as an implicit, undocumented invariant.
- **Skip `CONFIG_ORPHANED_PATH` for any argument matching `/\.\.\.$/`,
  regardless of adapter.** Rejected: this would weaken the check for every
  command, including ones where a literal `...`-suffixed argument really is
  a missing path unrelated to Go; scoping to `command.adapter === 'go-test'`
  keeps the exemption precise to the syntax that motivates it.

## Consequences

- Go and Rust test functions can use descriptive names with the ID embedded
  anywhere before further identifier characters, matching the flexibility
  already available to vitest/jest/pytest/junit test titles.
- `config lint` no longer reports a false `CONFIG_ORPHANED_PATH` for a
  go-test command's `./...` package-pattern argument, while every other
  command's orphaned-path detection is unchanged.
