# ADR-0005: Normalize Copilot routine shutdown lifecycles as terminal evidence

## Context

MUSUBIX3 strict workflow verification requires a final `result` event, but
current GitHub Copilot CLI session logs terminate with `session.shutdown`.
When a conversation is resumed, the same session JSONL can also contain one or
more routine shutdowns followed by `session.resume` before the final shutdown.
Routine shutdown logs retain the session UUID in the session lifecycle and
provide an explicit shutdown classification.

## Decision

Support both terminal formats. Preserve the existing `result` contract. For the
Copilot shutdown format, validate a single-session lifecycle state machine:
exactly one `session.start`, zero or more routine shutdown/resume episodes, and
one final routine shutdown. Every non-final shutdown must be followed by a
`session.resume` as the next non-empty JSONL event. Resume and shutdown UUIDs
remain optional for compatibility with current Copilot logs but must match the
start UUID when present. Retain the existing strict event timestamp validation
and tool-to-final-shutdown skew bound without introducing a new lifecycle-wide
timestamp ordering rule. Normalize only the final routine shutdown to exit code
zero after validating the unmodified complete transcript.

The sanitizer first reuses strict verification against the complete unmodified
input, then retains `session.resume` in a minimal strict-valid shape. When
identity replacement is requested, it rewrites `session.start` and any resume
or shutdown UUID that is present. Reusing the verifier prevents discarded
events from turning an invalid source lifecycle into valid strict evidence.

## Rejected alternatives

- Manually append `result`: rejected because it changes the evidence source.
- Treat every shutdown as successful: rejected because abnormal termination
  would become success-shaped evidence.
- Ignore intermediate shutdowns: rejected because resumed conversations would
  remain unverifiable.
- Define adjacency only after sanitization: rejected because removed events
  could conceal an invalid source lifecycle.
- Disable strict mode: rejected because session identity and terminal integrity
  would no longer be enforced.

## Consequences

- Current Copilot CLI logs can provide strict workflow evidence.
- Resumed conversations remain verifiable without editing the source
  transcript.
- Older `result` transcripts remain supported.
- Sanitized evidence carries explicit resume boundaries and preserves lifecycle
  validity.
- Future shutdown schema changes fail closed until explicitly supported.
