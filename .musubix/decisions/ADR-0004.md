# ADR-0004: Build the article around one evidence-backed large-scale system

## Context
A feature-list article would explain MUSUBIX3 superficially but would not prove that its workflow helps with large-scale AI Coding. The requested article must be useful to both beginners and technical leaders and must be based on an actual natural-language development exercise.

## Decision
Use one multilingual e-commerce marketplace as the article's through-line. Create the title and table of contents first, obtain review, then implement the example and write the long-form article from measured evidence. Keep the application under `examples/` so readers can inspect and reproduce it.

## Rejected alternatives
- Reuse only prior experiments: rejected because the requested architecture and current MUSUBIX3 behavior would not be demonstrated directly.
- Use several small applications: rejected because cross-service design, CI/CD, observability, security, and change impact would remain fragmented.
- Write the full article before implementation: rejected because claims could become speculative or require substantial rewriting.

## Consequences
- The first deliverable is an outline rather than a completed article.
- The repository will gain a substantial example application.
- The final article can link every major claim to a reproducible artifact or command result.
