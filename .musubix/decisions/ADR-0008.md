# ADR-0008: Resolve per-test TDD fingerprints via AST call-expression lookup, not marker-slice heuristics

## Context

`testFingerprint()` (`packages/analysis/src/tdd.ts`) computes the hash used
by `TDD_TEST_STALE` detection. For a test declared as a top-level statement,
it correctly hashes only that statement's text. For a test nested inside a
shared `describe(...)` block — the normal Vitest/Jest style used throughout
this repository's own test suite — no top-level statement starts at the
test's own line, so the code falls back to a heuristic: slice from the
test's leading `@id TEST-*` comment forward to the *next* occurrence of the
same comment pattern (or end of file).

That heuristic ties an untouched test's fingerprint to the position of its
*neighbors*. Adding a new test after an existing one, or reordering/removing
a sibling test, shifts where the "next marker" falls, changing how much
trailing boilerplate (closing braces, blank lines, subsequent code) is
captured in the slice. GitHub Issue #1 (v0.1.10 evidence-debt review) found
exactly this: `TEST-CLI-WORKFLOW-UX-001` through `005` reported
`TDD_TEST_STALE` because `tests/cli-workflow-ux.test.ts` gained additional
tests after their cycles were recorded — none of the flagged tests' own
bodies had changed.

## Decision

Resolve the fingerprinted span by walking the full AST (not just top-level
statements) to find the call expression whose test declaration the
annotation comment documents, using the same line/column anchor already
computed from the `TraceNode`, and hash the text from the annotation comment
through the end of that call expression. This scopes the fingerprint to
exactly one test's own declaration regardless of nesting depth, so sibling
tests before or after it in the same `describe(...)` block cannot affect it.
Keep the existing comment-marker-slice logic only as a fallback for
non-source test files (e.g. markdown/plain-text test reports) where no AST
is available.

## Rejected alternatives

- **Keep the marker-slice heuristic, but stop at the first blank line or
  closing brace run.** Rejected: still heuristic and language-specific;
  would not generalize past the two-space Vitest/Jest indentation style used
  today, and could still misfire on multi-line assertions containing blank
  lines.
- **Hash the whole test file per test ID.** Rejected: this is the failure
  mode we are removing at one level up — it would mark every test in a file
  stale whenever any one test in that file changes, which defeats the
  purpose of per-test staleness detection entirely.
- **Require exactly one test per file (no nested `describe` blocks).**
  Rejected: breaking change to this repository's own ~330-test suite and to
  every existing user project; MUSUBIX3 must fit existing test-authoring
  conventions, not dictate a new one.
- **Re-anchor by test *name* string match instead of AST position.**
  Rejected: two tests can share a name prefix (e.g. copy-pasted cases), and
  name-based matching would not survive a rename that is itself part of a
  legitimate Refactor phase, unlike a stable line/AST anchor recomputed from
  the trace node the annotation already produces.

## Consequences

- Every *pre-existing* recorded fingerprint for a nested test — including
  `TEST-CLI-WORKFLOW-UX-001` through `006`, and every other nested test in
  this repository's own evidence (`TEST-HUMAN-APPROVAL-GATES-001`–`008`,
  `TEST-SESSION-SCOPED-DEVELOPMENT-002`, `TEST-WORKFLOW-SHUTDOWN-001`) — was
  computed under the old fallback heuristic (slice to the next `@id TEST-`
  marker or EOF) and no longer matches the new AST-scoped computation, even
  when the test's own source is unchanged, because the hashed byte range
  differs under the new algorithm. Every such cycle reads as
  `TDD_TEST_STALE` immediately after this fix lands. Recording a fresh
  Red/Green (or Refactor) for these untouched, working tests would fabricate
  a failure that never genuinely occurred, which the constitution's TDD
  evidence rules forbid. `ADR-0009` / `REQ-TDD-FINGERPRINT-MIGRATION-001`
  introduces a narrow, explicit, human-approved migration operation that
  updates only the stored fingerprint value for such cycles, after proving
  (by recomputing the superseded algorithm against current source) that no
  real drift occurred — this fix does not retroactively repair stored
  evidence by itself; the migration operation does that, deliberately kept
  as a separate, auditable step.
- Fingerprint computation for non-source or non-AST-resolvable tests is
  unchanged; this ADR only tightens the source-file, nested-declaration case.
