# ADR-0044: 開発依存の js-yaml override を一つの例外として pin する

## Context

CHANGE-0052 の承認済み REQ-AUDIT-OVERRIDE-CONTRACT-001..004 は、
GHSA-hp3w-g68c-fv3c の `sprintf-js` DoS 経路を除去し、
本番依存・distribution・Vitest の既存契約を保持する。
Jest の devDependency 経路は `@istanbuljs/load-nyc-config` から
`js-yaml@3.15.2 > argparse@1.0.10 > sprintf-js@1.0.3` に達する。
sprintf-js は公開済み全バージョンが advisory の affected range 内で、
直接更新による固定版はない。

`@istanbuljs/load-nyc-config` は `js-yaml: "^3.13.1"` を要求するが、
YAML 読み込み点は CommonJS `require("js-yaml").load(readFileText)` である。
`js-yaml@5.4.3` の dependency は argparse 2.x だけで、
argparse 2.0.1 は dependency を持たない。この二 major 範囲外更新は
API 名だけで安全と判断できないため、consumer 経由の代表 YAML 入力、
native Jest、全 tests、実 package archive を実際に検証する必要がある。

ADR-0036 は version-coupled な @vitest/mocker だけの override を却下した。
その判断は維持し、今回の js-yaml 例外を Vitest/fork 一般許可に拡大しない。
既存 npm-audit-remediation 設計の blanket overrides 不在制約は、
この ADR と新設計で narrow exception に更新する。

## Decision

1. root manifest の唯一の override を `{"js-yaml":"^5.4.3"}` に固定する。
   npm 生成 lockfile の全 root/nested YAML/argparse レコードをオフラインで
   検査し、旧 graph や sprintf-js 再混入を `LOCK_OVERRIDE_GRAPH` で拒否する。
   manifest の別値/追加/不正型は `MANIFEST_CONTRACT` で拒否する。
2. root lock metadata は実 install 後の一度の観測
   （対象 current lockfile digest ごと）を証拠に pin する。
   設計時の npm 11.19.0 と追加前 metadata の観測から、本設計は
   root overrides 不在を予定するが、追加後結果を偽って断定しない。
   一致すれば root へのあらゆる挿入を拒否する。
   異なれば予定 pin を修正し設計再承認を得るまで実装を進めない。
   両表現を許す fallback や、自作 root metadata の追加は禁止する。
3. CHANGE-0022 は一つの living lockfile-bound audit summary を保持する。
   元 advisory/検証履歴を消さず capture/digest/real zero counts を更新し、
   CHANGE-0052 に新 GHSA と remediation history を記録して相互参照する。
   未加工実 audit JSON を保持し、offline checker はそれと文書の整合のみを
   確認する。実 npm audit を deterministic test 内には持ち込まない。
4. new CODE/TEST/REQ/DES は authoritative checker と tests に付ける。
   新しい agent runtime、dependency manager、watcher、別の evidence store は
   導入せず、既存 Copilot/CLI/trace/evidence 機構を利用する。
5. npm-version/root representation の変更や追加 YAML consumer は黙認しない。
   前者は再観測と証拠更新、pin 変更時は設計再承認、後者は同等実行証拠まで
   readiness を阻止する。
6. native Jest case は runner/adapter 統合だけを確認し、coverage 無効の実行で
   js-yaml が通るとは主張しない。YAML callsite は実 consumer 公開 API で検証する。
   compatibility/archive evidence は install 後、実 audit と同じ current
   lockfile digest に拘束し、旧 tree や旧 digest の結果を受容しない。
   installed-tree と npm/root metadata 観測も同じ digest/取得順に拘束し、
   lock bytes 変更時は再観測する。consumer inventory の全件性は文書上の
   assertion ではなく、同じ lockfile から導出した集合との一致で検査する。

## Rejected alternatives

- **dev-only なので放置する:** production exposure と開発時の脆弱コード除去を
  混同するため却下。互換性を検証できる maintained replacement がある。
- **sprintf-js を固定版に上げる:** そのような公開バージョンは現在存在しない。
- **npm audit の Jest major downgrade / --force を受容する:** native adapter の
  scope と reviewed dependency surface を変えるため却下。
- **すべての overrides を許可する / guard を削除するだけ:** 未レビュー値まで
  通る security contract 緩和になるため却下。
- **js-yaml の method 名だけで compatibility を宣言する:** `.load()` の
  存在は YAML semantics や surrounding tooling 実行成功を証明しない。
- **旧 CHANGE-0022 の digest を維持し、新 CHANGE へのリンクだけ追加する:**
  REQ-NPM-AUDIT-REMEDIATION-002 と既存 checker の current bytes binding に反する。
- **毎回 registry audit を unit tests で実行する:** network/future advisory を
  deterministic test に持ち込むため却下。実 audit は verification/monitoring。
- **npm root の overrides metadata を独自に作る / 両表現を受容する:**
  実生成物を変え、metadata drift が検出不能になるため却下。

## Consequences

レビュー済み例外が一つ増えるが、許容 dependency surface は exact pin を保つ。
lockfile 更新のたびに実 audit/digest の更新が必要になる。
将来の js-yaml 5.x metadata/consumer drift は checker 又は compatibility 検証を
止めるため、レビュー負担を受容して未検証 graph の silent acceptance を防ぐ。
zero audit は当該時点の registry 結果に限り、未知脆弱性や universal unreachability
を証明しない。weekly/manual audit policy と release 前の再確認を維持する。
この ADR の設計は human design approval 待ちであり、依存更新の許可ではない。
別の package が argparse 1.x/sprintf-js を導入した場合、js-yaml override だけでは
除去できない。checker を緩めず readiness を阻止し、その consumer の reachability
と remediation を新たにレビューする。必要な dependency surface 変更は別の明示的
承認で扱い、今回の例外の拡張として黙認しない。
