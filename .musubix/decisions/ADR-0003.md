# ADR-0003: Explicit change identity for session reuse

## Context
A Copilot session can contain multiple unrelated program requests. Conversational continuity and old evidence are not reliable indicators that a new request continues the prior change.

## Decision
Treat each natural-language development request as a new change unless the user explicitly names the existing `CHANGE-*` ID and requests continuation. Route new requests to fresh requirements elicitation and do not reuse prior approvals or phase evidence.

## Consequences
Unrelated requests cannot inherit stale requirements or approvals. Continuing a change requires an explicit identifier, while prior artifacts remain available only as historical context.

## Requirements
REQ-SESSION-SCOPED-DEVELOPMENT-001, REQ-SESSION-SCOPED-DEVELOPMENT-002
