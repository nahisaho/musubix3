# Change Quality checkpoint refresh design

## DES-CHANGE-QUALITY-REFRESH-001: Versioned Quality lineage model
Responsibilities: Extend `ChangeRecord` with optional non-empty `qualityHistory` containing retained Quality checkpoints in ascending order; keep the newest checkpoint in `phases.quality`; expose pure helpers that return the complete lineage, ordinal order identity, authoritative checkpoint, and identity-to-payload resolution; load legacy schema version 1 and refreshed schema version 2 with deterministic shape/version errors.
Interfaces: `qualityLineage(change) -> ChangePhaseEvidence[]`; `qualityIdentity(ordinal) -> "quality" | "quality:N"`; `qualityPayloadForIdentity(change, identity) -> ChangePhaseEvidence | undefined`; `qualityOrderIdentity(change, checkpoint) -> string`; `ChangeEvidence.schemaVersion: 1 | 2`; `ChangeRecord.qualityHistory?: ChangePhaseEvidence[]`.
Constraints: `qualityHistory` is absent for a single checkpoint and non-empty otherwise. Persisted history entries are immutable retained `phase: "quality"` payloads with integer orders, and persisted `phases.quality` always has the greatest Quality order; a dry-run projection may omit the candidate checkpoint's `order` and is exempt from persisted-order invariants. `qualityPayloadForIdentity` maps `quality` to `qualityHistory[0]` when history exists and otherwise to `phases.quality`; it maps `quality:N` to `qualityHistory[N - 1]` when present and otherwise to `phases.quality` only for the final authoritative ordinal. `qualityOrderIdentity` finds the exact checkpoint object by reference identity within `qualityLineage(change)` and throws on a miss; it never falls back to `quality`. Callers resolve identity against the checkpoint's owning `ChangeRecord` before cloning or rewriting payloads; cloned checkpoints must be resolved against the cloned owning record rather than an earlier instance. The loader accepts schema versions 1 and 2, rejects malformed top-level version/changes fields with the existing invalid-evidence error, and throws `CHANGE_EVIDENCE_SCHEMA_UNSUPPORTED` for integer versions above 2; it deliberately defers version-1-with-history and all Quality-history shape/linkage checks to change validation and merge input validation so their required diagnostics remain reachable. Pure helpers own ordinal mapping so recorder, validator, merge, and tests cannot diverge.
Requirements: REQ-CHANGE-QUALITY-REFRESH-001 REQ-CHANGE-QUALITY-REFRESH-003
ADRs: ADR-0034
Depends-On: none

## DES-CHANGE-QUALITY-REFRESH-002: Atomic Quality refresh recording
Responsibilities: Extend the Quality branch of `recordChangePhase` to distinguish initial recording from refresh; bypass the generic one-shot duplicate guard only for an existing Quality checkpoint; validate exact full scope, lineage, current Green coverage, and newer Green in the required precedence; create coordinated order/change candidates; append the prior authoritative checkpoint to history and install the candidate as authoritative; commit both evidence files through a recoverable two-file transaction; project the same schema-version-2 result in dry-run without writing or reserving an order. Initial Quality keeps the existing union coverage and legacy check ordering, while refresh uses the new scope-first precedence.
Interfaces: `recordChangePhase(root, changeId, "quality", requirementIds, options) -> Promise<ChangeEvidence>` remains the public API; internal `prepareQualityRefresh(change, evidence, order, fingerprints, dryRun)` returns projected change and order candidates; `recoverQualityRefresh(root) -> Promise<{ recovered: boolean; action: "nothing-to-recover" | "rolled-back" | "rolled-forward" }>`; CLI leaf `change quality-recover [--json]`; shared transaction helpers commit or recover candidate evidence; plain Error prefixes are `CHANGE_QUALITY_REFRESH_LINEAGE_INVALID`, `CHANGE_QUALITY_REFRESH_GREEN_MISSING`, `CHANGE_QUALITY_REFRESH_NOT_NEEDED`, `CHANGE_QUALITY_REFRESH_RECOVERY_REQUIRED`, and `CHANGE_QUALITY_REFRESH_RECOVERY_UNSAFE`.
Constraints: Initial Quality retains the legacy union-across-batches rule and `quality` order identity. Refresh scope validation precedes lineage, current Green, and newer-Green checks. The lineage check rejects schema-version-1 evidence carrying `qualityHistory` as `CHANGE_QUALITY_REFRESH_LINEAGE_INVALID` rather than silently upgrading malformed evidence. Current Green is selected with the existing greatest-Red-order batch helper. The existing pre-write integer-order guard scans Quality history as well as singular phases and batches. The recorder reads validated order evidence inside the writer lock, while dry-run uses a coordinated evidence read. Refresh uses a dedicated `.quality-refresh-transaction.json` journal with an explicit journal kind and only `order.json`/`changes.json` targets; it reuses extracted prepared/committed, fsync, rollback, roll-forward, candidate-validation, digest-guard, and dependency-injected fault primitives from evidence merge without sharing the merge journal path or target schema. `change quality-recover` is classified as a writer-lock operation and is the only refresh recovery surface; add it consistently to `EVIDENCE_OPERATION_CLASSIFICATION`, `EVIDENCE_WRITER_ANALYSIS_ENTRIES`, and exact CLI-leaf coverage. The shared evidence-path readiness guard rejects a published refresh journal before any guarded reader/writer inspects evidence; refresh recovery bypasses only its own guard through validated absolute paths and raw filesystem operations, while still rejecting a merge journal. Ordinary commands and `evidence merge --recover` seeing only a refresh journal fail `CHANGE_QUALITY_REFRESH_RECOVERY_REQUIRED`; either recovery command seeing both journals fails `CHANGE_QUALITY_REFRESH_RECOVERY_UNSAFE`; a refresh command seeing only a merge journal retains `EVIDENCE_MERGE_RECOVERY_REQUIRED`. Lock-protected publication preconditions prevent coexistence. Persisted refresh writes schema version 2; dry-run emits schema version 2 with no candidate order.
Requirements: REQ-CHANGE-QUALITY-REFRESH-001 REQ-CHANGE-QUALITY-REFRESH-002 REQ-CHANGE-QUALITY-REFRESH-003
ADRs: ADR-0034
Depends-On: DES-CHANGE-QUALITY-REFRESH-001

## DES-CHANGE-QUALITY-REFRESH-003: Lineage-aware validation and evidence merge
Responsibilities: Validate every retained and authoritative Quality checkpoint against its ordinal order record; use authoritative Quality for all chronology/completeness checks; include retained timestamps in recordedAt-order warnings; teach evidence merge input validation, explicit Quality payload resolution, deduplication, lineage-prefix comparison, sequence remapping, cloned-change rewriting, candidate-reference validation, and output version selection about Quality lineages; update the SDD change Skill guidance, README command references in both languages, and CHANGELOG, including the requirement to refresh Quality in a branch/worktree before merging evidence that contains post-Quality corrective batches.
Interfaces: `validateChangeEvidence(root)` and `validateChangeCompleteness(root)` signatures remain unchanged; malformed lineage reached through those validation paths emits `CHANGE_QUALITY_HISTORY_MALFORMED`, while Quality lineage or pairing failures reached through merge input validation emit `EVIDENCE_MERGE_CONFLICT`; `.github/skills/sdd-change/SKILL.md`, `README.md`, `README-ja.md`, and `CHANGELOG.md` document refresh usage and limitations.
Constraints: Legacy schema-version-1 single-checkpoint results remain unchanged. Quality validation replaces the singular-phase `quality` pairing rather than running in addition to it. Lineage comparison is the single authoritative source of Quality divergence conflicts; plan-level logical payload matching delegates Quality identities to that resolver and sets `revalidationRequired` consistently with retained incoming Quality payloads. Merge compares Quality by ordinal identity and payload excluding remapped `order`, accepts exact-prefix lineages, preserves the longer valid lineage, and rejects divergence, gaps, and orphans within each merged change's Quality lineage before writes. The orphan check applies only to Quality order records for change IDs present in `changes.json`; order records whose change ID has no change entry remain outside this feature's orphan scope. Merge rewrites history and authoritative orders in base/incoming/whole-change paths and outputs schema version 2 whenever either input is version 2 or history exists. `qualityOrderIdentity` is index-based over `qualityLineage`, including dry-run checkpoints without an order; callers use the checkpoint and owning change from the same object graph. RecordedAt labels use ordinal identities and preserve the bare `quality` label for legacy evidence. `CHANGE_PHASE_ORDER` remains non-waivable.
Requirements: REQ-CHANGE-QUALITY-REFRESH-003
ADRs: ADR-0034
Depends-On: DES-CHANGE-QUALITY-REFRESH-001 DES-CHANGE-QUALITY-REFRESH-002
