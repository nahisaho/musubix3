# Design / 設計

## DES-APPROVAL-PREPARE-DIFF-ONLY-001: Diff computation reusing a generalized drift helper
Responsibilities: Rename the existing module-private `releaseDrift(approved, current)` helper in `approval.ts` to `artifactDrift(approved, current)` (pure rename, identical signature and behavior — it already only compares two generic `Record<string, string>` artifact maps and has no release-specific logic), updating its sole existing caller (`validateReleaseApprovalForTag`) to the new name with no behavior change. Add a new function, `diffOnlyChangedFiles(manifest: ApprovalManifest, previous: ApprovalEvidence | null): { changedFiles: string[]; diffOnlyBaseline: 'none' | 'approved' }`, built on `artifactDrift` rather than re-implementing path/hash comparison from scratch. When `previous` is `null` (no prior approval recorded for this exact stage/domain), return `{ changedFiles: Object.keys(manifest.artifacts).sort(codePointOrder), diffOnlyBaseline: 'none' }`. When `previous` is present, return `{ changedFiles: artifactDrift(previous.artifacts, manifest.artifacts).map((d) => d.path), diffOnlyBaseline: 'approved' }` — `artifactDrift` already returns one entry per path that differs (added/modified/deleted), pre-sorted by `codePointOrder` and free of duplicates, so no additional sort/dedup step is needed.
Interfaces: `export function diffOnlyChangedFiles(manifest: ApprovalManifest, previous: ApprovalEvidence | null): { changedFiles: string[]; diffOnlyBaseline: 'none' | 'approved' }`. `artifactDrift` (renamed from `releaseDrift`) keeps its exact existing signature and behavior, remains module-private (not exported), and gains exactly one more call site.
Constraints: This function is pure and read-only: it never mutates `manifest.artifacts`/`manifest.artifactSha256`, never writes evidence, and never re-reads the filesystem (both `manifest` and `previous` are passed in already loaded). Corrupted/invalid prior approval evidence is detected upstream, before this function is ever called, by the existing `loadApproval` (which already throws `Invalid <stage> approval evidence.` on schema failure) — this component has no special-case handling of that condition itself, which is what makes REQ-APPROVAL-PREPARE-DIFF-ONLY-007 true by construction rather than by an added try/catch: there is no silent-fallback branch to remove.
Requirements: REQ-APPROVAL-PREPARE-DIFF-ONLY-002, REQ-APPROVAL-PREPARE-DIFF-ONLY-003, REQ-APPROVAL-PREPARE-DIFF-ONLY-004, REQ-APPROVAL-PREPARE-DIFF-ONLY-007
ADRs: ADR-0043
Depends-On: none

## DES-APPROVAL-PREPARE-DIFF-ONLY-002: CLI wiring and domain-scoped baseline resolution
Responsibilities: Add a `--diff-only` boolean option to the `approval prepare <stage>` command in `main.ts`. When set, after computing `manifest` via the existing unmodified `approvalManifest(root, stage, domain)` call, additionally call the existing `loadApproval(root, stage, domain?.name)` (the same function and domain-path resolution `validateApprovalStage` already uses) to obtain `previous: ApprovalEvidence | null`, then call `diffOnlyChangedFiles(manifest, previous)` and merge its `{ changedFiles, diffOnlyBaseline }` into the output object alongside `manifest`'s unmodified fields (`stage`, optional `domain`/`features`, `artifacts`, `artifactSha256`). `domain` is resolved exactly once per invocation, identically for both the manifest and the baseline lookup (no separate or duplicated domain-resolution logic for diff-only); for `release`, `domain` is always `undefined`, matching the existing release-stage behavior and `requireDomainOption`'s existing rejection of `--domain` for `release`.
Interfaces: `approval prepare <stage> [--domain <name>] [--diff-only]`. The JSON output type becomes `ApprovalManifest & { changedFiles?: string[]; diffOnlyBaseline?: 'none' | 'approved' }` — `changedFiles`/`diffOnlyBaseline` are present if and only if `--diff-only` was passed; omitting `--diff-only` produces byte-identical output to the current (pre-change) command.
Constraints: `loadApproval`'s existing thrown `Invalid <stage> approval evidence.` error is allowed to propagate unchanged and abort the command with a nonzero exit; nothing in this component catches, downgrades, or converts it into a `diffOnlyBaseline: 'none'` fallback (REQ-APPROVAL-PREPARE-DIFF-ONLY-007). `--diff-only` has no effect on `artifactSha256`/`artifacts` — both are computed by the same, call exactly as without the flag (REQ-APPROVAL-PREPARE-DIFF-ONLY-002).
Requirements: REQ-APPROVAL-PREPARE-DIFF-ONLY-001, REQ-APPROVAL-PREPARE-DIFF-ONLY-002, REQ-APPROVAL-PREPARE-DIFF-ONLY-005
ADRs: ADR-0043
Depends-On: DES-APPROVAL-PREPARE-DIFF-ONLY-001

## DES-APPROVAL-PREPARE-DIFF-ONLY-003: Console summary rendering
Responsibilities: Change the non-JSON human-readable summary printed by `approval prepare <stage>` (the `output(manifest, !!options.json, summary)` call in `main.ts`) so that, when `--diff-only` is set and `--json` is not, the summary lists only `changedFiles` (one path per line), preceded by a short header line containing the full `artifactSha256` and an explicit statement of `diffOnlyBaseline` (distinguishing "no prior approval found; showing all current artifacts" from "compared against the previously recorded approval"). When `--diff-only` is not set, the summary is completely unchanged from the current behavior (the full `Object.keys(manifest.artifacts)` listing).
Interfaces: A local summary-string branch in the `approval prepare` CLI action, keyed on `options.diffOnly`; no new exported function (presentation-only, CLI-local).
Constraints: `--json` output is never affected by this component — `--json --diff-only` always returns the full merged object from DES-APPROVAL-PREPARE-DIFF-ONLY-002 regardless of how the non-JSON summary is rendered.
Requirements: REQ-APPROVAL-PREPARE-DIFF-ONLY-006
ADRs: none — presentation-only console formatting change with no architectural decision or tradeoff to record
Depends-On: DES-APPROVAL-PREPARE-DIFF-ONLY-002
