# Design / 設計

## DES-REQUIREMENTS-DESIGN-SCAFFOLD-001: Feature artifact scaffold / 機能成果物の雛形生成
Responsibilities: Validate a feature slug (and, for `requirements scaffold`, an optional `--title`), then atomically create exactly one of `.musubix/features/<slug>/requirements.md` or `.musubix/features/<slug>/design.md` from a fixed placeholder template, creating missing parent directories but never overwriting an existing target file, even under a concurrent create.
Interfaces: `scaffoldRequirements(root, slug, options?: { title?: string }): Promise<string>` and `scaffoldDesign(root, slug): Promise<string>` in `packages/analysis/src/scaffold-artifact.ts`, each resolving to the written path relative to `root` (`.musubix/features/<slug>/requirements.md` / `design.md`) or rejecting with an `Error`. `scaffoldRequirements` writes: front matter `schemaVersion: 1` / `feature: <slug>`; heading `## REQ-<SLUG>-001: <title>` (`<title>` defaults to `Describe the requirement` when `--title` is absent, `<SLUG>` is `<slug>` upper-cased); `Priority: must`; `Type: functional`; `Pattern: ubiquitous`; `Statement: The system shall TODO: describe the required behavior.`; `Acceptance: TODO: describe how this requirement will be verified.`. `scaffoldDesign` writes the same front matter; heading `## DES-<SLUG>-001: Describe the component`; `Responsibilities:`/`Interfaces:`/`Constraints:` each `TODO: describe the component's <field>.`; `Requirements: REQ-<SLUG>-001`; `ADRs: none — TODO: record a decision if one becomes relevant.`; `Depends-On: none`. `scaffoldDesign` does not require a matching `requirements.md` to already exist; if absent, the generated `design.md` will fail cross-file `musubix3 design validate` (unknown requirement link) until the requirement is added — this is the intentionally simpler contract, not a defect. Exposed as `musubix3 requirements scaffold <slug> [--title <text>]` and `musubix3 design scaffold <slug>` in `packages/cli/src/main.ts`, using the shared `common()` `--root`/`--json` options, printing the returned relative path on success, and letting thrown errors flow through the existing top-level CLI error handler (non-zero exit, message on stderr).
Constraints: Slugs must match `^[a-z0-9]+(-[a-z0-9]+)*$` (same rule as `install()` in `packages/cli/src/install.ts`) or the call rejects with `Invalid feature slug "<input>": must be lowercase kebab-case, e.g. "my-feature".` before any filesystem access. A supplied `--title` must be non-empty after trimming and contain no `\r`/`\n`, or the call rejects with `Invalid --title "<input>": must be a non-empty, single-line value.` before any filesystem access. The target file is created with an OS-level exclusive-create flag (`wx`) so an existing file — including one created concurrently after any prior existence check — is never overwritten; on conflict the call rejects with `Refusing to overwrite existing file: <relative-path>` and leaves the existing file's bytes unchanged. Placeholder content is a fixed template that must pass `validateRequirements`/`validateDesign` unmodified.
