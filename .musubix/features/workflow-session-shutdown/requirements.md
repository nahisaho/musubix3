# Copilot session shutdown workflow requirements

## REQ-WORKFLOW-SHUTDOWN-001: Strict routine shutdown terminal evidence
Priority: must
Type: functional
Statement: GitHub Copilot CLIの完全な単一セッションログをstrict Workflow検証するとき、システムはAcceptanceに定義する成功`result`形式またはroutine shutdown形式のいずれか一方だけを正常終了として受理しなければならない。
Acceptance: strict検証が、従来の単一final `result(exitCode=0)`形式、単一final routine shutdown形式、および1回以上のroutine shutdown/resume組を経てfinal routine shutdownに至る形式で成功すること。routine shutdownはshutdown eventの`data.shutdownType`が文字列`routine`と厳密一致するものに限定し、欠落または他の値を拒否すること。shutdown形式は、任意の非terminalかつ非lifecycleイベント、既存strict UUID形式検査に合格するUUIDを持つ一意な`session.start`、0回以上の「任意の非terminalイベント、routine shutdown、その次の非空行にあるresume」の組、任意の非terminalイベント、final routine shutdownから成り、final routine shutdownのみを成功terminalとしてexit code 0へ正規化すること。空白のみの行は隣接判定とfinal event判定から除外し、非空行は未知typeを含めて隣接判定の対象とし、strictの既存規則どおり不正JSON、event type欠落、timestamp欠落または不正値をエラーとして拒否すること。`result`が最大1件であることとresult/shutdownの非混在を先に検査し、その後にshutdown件数を含むlifecycleを検査すること。`result`とshutdownの混在、複数のresult、shutdown形式でのsession startの欠落または重複、startより前のshutdown/resume、非routine shutdown、resumeと対にならない非final shutdown、shutdownの次の非空行ではないresume、直前のshutdownを持たないresume、lifecycleイベントに含まれるsession UUIDのsession startとの不一致、lifecycleイベントに2件以上のsession UUIDが現れること、final shutdown後のイベント、terminal event欠落をエラーとして拒否すること。session UUIDは各lifecycle eventで`data.sessionId`を優先し、無い場合だけtop-level `sessionId`を参照し、他のフィールドはsession UUIDとして扱わないこと。現行Copilot形式との互換性のためresumeとshutdownのsession UUIDは任意とするが、含む場合はsession startと一致すること。final shutdownにはstart前を含むtranscript全体で最も新しい先行tool eventとの既存`maxEventSkewMs`検査を維持し、`latestToolTimestamp - finalShutdownTimestamp > maxEventSkewMs`の場合だけ拒否すること。sanitizeは`result`形式およびshutdown形式の未加工入力に対する同一strict検証を先に再利用し、privacy-minimizedなskill tool eventsに加えて`session.start`、`session.shutdown`、`session.resume`の順序、shutdown type、および単一session identityを保持し、出力も同じterminal identityでstrict受理されること。sanitizeで非skill tool eventsを除外すると`latestToolTimestamp`は同じか古くなるため前記不等式を新たに満たすことはなく、残存tool eventに同じskew検査を適用すること。sanitizeは非final shutdownの次の非空行がresumeでない入力をfail-closedで拒否し、前記の不正なshutdown/resume系列を正常な系列へ変換してはならない。session identity置換時はsession startと、UUIDを含むresumeまたはshutdownを同じ置換UUIDへ書き換えること。
