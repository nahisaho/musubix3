# Explicit "no ADR needed" exemption for design components design

## DES-DESIGN-ADR-NONE-EXEMPTION-001: Recognize and validate an explicit "none — <reason>" ADRs marker
Responsibilities: In `validateDesign()` (`packages/domain/src/design.ts`), after computing a component's `decisions` list via `references(field(s.body, 'ADRs|ADR|決定'), 'ADR')`, also inspect the raw `ADRs` field text captured by `field()` for the exemption marker: the text trimmed matches `/^none(?:\s*[-–—:]\s*(.*))?$/i` (case-insensitive, allowing a hyphen, en dash, em dash or colon separator). When the marker matches and the captured reason (trimmed) is non-empty and is not a placeholder (`TODO`, `TBD`, `N/A`, `未定`, case-insensitive, matched as the whole trimmed reason), treat the component as exempt: expose the reason as the shared parsed exemption result and skip the existing `DES_ADR` check even though `decisions` is empty. When the marker matches but the reason is missing or is a placeholder, expose no exemption result and push `DES_ADR_EXEMPTION_REASON` instead of `DES_ADR`.
Interfaces: `validateDesign(text: string, path?: string, context?: DesignContext): Validation<Component[]>` remains unchanged. `Component` adds optional `adrExemptionReason?: string`; it is present with the trimmed concrete reason only for a valid exemption and is absent for real ADR references, empty or unrecognized fields, and invalid exemption markers. This additive optional field preserves source compatibility for external `Component` literals. `Component.decisions` remains `string[]` and stays empty (`[]`) for an exempt component. Diagnostic code `DES_ADR_EXEMPTION_REASON` remains unchanged.
Constraints: `adrExemptionReason` is the only parsed exemption result consumed outside design validation; downstream checks must not duplicate the marker regex or placeholder list. Construct the optional property with a conditional spread to preserve `exactOptionalPropertyTypes`. Must not change behavior for any component whose `ADRs` field already contains at least one recognized `ADR-*` reference (the existing `DES_ADR`/`DES_ADR_LINK` checks and their diagnostics are unaffected, and `adrExemptionReason` is absent). Must not accept `none` as a value that also contains an `ADR-*` reference elsewhere in the same field (mixing the exemption marker with a real ADR reference is not a supported pattern; if `references()` finds at least one `ADR-*` id, the exemption marker is ignored and existing behavior applies unchanged). Must reject an entirely empty `ADRs` field exactly as before (`DES_ADR`), since an empty field does not match the `none` marker pattern. Confirm tests and generated evidence do not serialize `Component` wholesale as a fixed schema.
Requirements: REQ-DESIGN-ADR-NONE-EXEMPTION-001 REQ-DESIGN-ADR-NONE-EXEMPTION-002 REQ-DESIGN-ADR-NONE-EXEMPTION-003
ADRs: ADR-0017

## DES-DESIGN-ADR-NONE-EXEMPTION-002: Change-completeness exemption evidence
Responsibilities: In `validateChangeCompleteness()` (`packages/analysis/src/change.ts`), preserve the existing set of satisfying design IDs derived from `satisfies` trace edges. Treat a requirement as having ADR evidence when at least one satisfying design has either an incoming traced `decides` edge from a known ADR node or a present (non-`undefined`) `adrExemptionReason` from `validateDesign()`. Keep all other completeness checks and diagnostic text unchanged.
Interfaces: `validateChangeCompleteness(root)` retains its public signature and `CHANGE_COMPLETENESS_ADR` diagnostic. It consumes `Component.adrExemptionReason` from the existing `designsById` map populated by `validateDesign()`.
Constraints: Use existential semantics across the satisfying design IDs already derived from `satisfies` edges; those edges are equivalent to the component explicitly listing the requirement. A design ID absent from `designsById` contributes no exemption and produces no new diagnostic. An exemption counts exactly when that component's `adrExemptionReason` is present; file-level `validateDesign()` diagnostics are not consulted, matching the existing real-ADR path, while invalid exemption markers already leave the property absent. Do not infer exemptions from raw Markdown, an empty `decisions` array, missing design data, unknown ADR IDs, or placeholder/unrecognized ADR field values. A valid real ADR edge or a valid exemption is sufficient; neither path weakens concrete-design, implementation, test, TDD, performance, or other completeness checks. Add `CODE-DESIGN-ADR-NONE-EXEMPTION-002` with `@implements REQ-DESIGN-ADR-NONE-EXEMPTION-004` and `@design DES-DESIGN-ADR-NONE-EXEMPTION-002`; add `TEST-DESIGN-ADR-NONE-EXEMPTION-004` with `@verifies REQ-DESIGN-ADR-NONE-EXEMPTION-004`. The authoritative test covers a valid exemption, mixed real-ADR/exemption, and all five deterministic invalid forms from REQ-004.
Requirements: REQ-DESIGN-ADR-NONE-EXEMPTION-004
ADRs: ADR-0017
