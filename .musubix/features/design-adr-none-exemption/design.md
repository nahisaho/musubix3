# Explicit "no ADR needed" exemption for design components design

## DES-DESIGN-ADR-NONE-EXEMPTION-001: Recognize and validate an explicit "none — <reason>" ADRs marker
Responsibilities: In `validateDesign()` (`packages/domain/src/design.ts`), after computing a component's `decisions` list via `references(field(s.body, 'ADRs|ADR|決定'), 'ADR')`, also inspect the raw `ADRs` field text captured by `field()` for the exemption marker: the text trimmed matches `/^none(?:\s*[-–—:]\s*(.*))?$/i` (case-insensitive, allowing a hyphen, en dash, em dash or colon separator). When the marker matches and the captured reason (trimmed) is non-empty and is not a placeholder (`TODO`, `TBD`, `N/A`, `未定`, case-insensitive, matched as the whole trimmed reason), treat the component as exempt: skip the existing `DES_ADR` check for that component even though `decisions` is empty. When the marker matches but the reason is missing or is a placeholder, push a new `DES_ADR_EXEMPTION_REASON` diagnostic instead of `DES_ADR`.
Interfaces: `validateDesign(text: string, path?: string, context?: DesignContext): Validation<Component[]>` (exported signature unchanged). New diagnostic code `DES_ADR_EXEMPTION_REASON`. `Component.decisions` remains `string[]` and stays empty (`[]`) for an exempt component. (DES-DESIGN-ADR-NONE-EXEMPTION-002 later adds a separate `Component.adrExempt` field; that addition is out of this component's scope.)
Constraints: Must not change behavior for any component whose `ADRs` field already contains at least one recognized `ADR-*` reference (the existing `DES_ADR`/`DES_ADR_LINK` checks and their diagnostics are unaffected). Must not accept `none` as a value that also contains an `ADR-*` reference elsewhere in the same field (mixing the exemption marker with a real ADR reference is not a supported pattern; if `references()` finds at least one `ADR-*` id, the exemption marker is ignored and existing behavior applies unchanged). Must reject an entirely empty `ADRs` field exactly as before (`DES_ADR`), since an empty field does not match the `none` marker pattern.
Requirements: REQ-DESIGN-ADR-NONE-EXEMPTION-001 REQ-DESIGN-ADR-NONE-EXEMPTION-002 REQ-DESIGN-ADR-NONE-EXEMPTION-003
ADRs: ADR-0017

## DES-DESIGN-ADR-NONE-EXEMPTION-002: Propagate the "none" exemption into the change-completeness gate
Responsibilities: Expose the exemption computed by DES-DESIGN-ADR-NONE-EXEMPTION-001 on the parsed `Component` so the `change-completeness` gate check can see it without re-parsing markdown. In `packages/domain/src/design.ts`, add a boolean `adrExempt` to each returned `Component`: `true` only when `decisions` is empty and the raw `ADRs` field matches the valid "none — <reason>" exemption pattern (same regex and placeholder rules as DES-DESIGN-ADR-NONE-EXEMPTION-001); `false` otherwise (including the invalid "none" and "none — TODO/TBD/N/A/未定" cases). In `packages/analysis/src/change.ts`'s `validateChangeCompleteness`, for each requirement, keep the existing `hasAdr` computation that accepts a `decides` trace edge from any ADR node targeting any design component satisfying the requirement; additionally accept the requirement's ADR obligation as satisfied when no such `decides` edge exists but at least one design component satisfies the requirement and every one of those components has `adrExempt === true`.
Interfaces: `Component.adrExempt: boolean` (new required field on the existing `packages/domain/src/types.ts` `Component` interface). `validateChangeCompleteness` behavior only (no new exported function or CLI flag).
Constraints: Must not change `CHANGE_COMPLETENESS_ADR` outcomes for any requirement where at least one of its satisfying design components already has a real `decides` trace edge (exemption only ever adds acceptance, never removes an existing pass or converts a pass to a fail). Must not accept a requirement as ADR-complete when any one of its satisfying design components has neither a `decides` edge nor a valid exemption, even if other components satisfying the same requirement are exempt or linked.
Requirements: REQ-DESIGN-ADR-NONE-EXEMPTION-004
ADRs: none — this reuses the exemption-detection regex and validity rules already decided for `validateDesign` in the sibling component above, exposing the existing decision as a field rather than introducing a new architectural boundary.
