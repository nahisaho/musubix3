# Design: Durable workflow reconciliation across resumed sessions

## DES-WORKFLOW-RESUMED-SESSION-DURABILITY-001: Reconciliation schema, canonicalization, and validation
Responsibilities: Extend `WorkflowManifest` in `packages/analysis/src/workflow-types.ts` with `WorkflowReconciliation`, `WorkflowLedgerInvocation`, `WorkflowInvocationSource`, and `WorkflowDeclarationBinding`. Export `workflowReconciliationLimits = { maxInvocations: 10000, maxSources: 50000, maxBytes: 16777216 }`. Validate the closed schema, ISO timestamps, terminal `completedAt` invariant, strict-source fields, canonical invocation/source/binding ordering, duplicate identities, `ledgerSha256`, `bindingsSha256`, and canonical byte/count limits before any consumer uses reconciliation. Treat absent reconciliation as legacy-compatible and present invalid reconciliation as `WORKFLOW_RECONCILIATION_MALFORMED` or `WORKFLOW_RECONCILIATION_LIMIT`.
Interfaces: `WorkflowManifest.reconciliation?: WorkflowReconciliation`; `workflowReconciliationLimits`; `canonicalizeWorkflowInvocations(invocations)`; `canonicalizeWorkflowBindings(bindings)`; `validateWorkflowReconciliation(reconciliation)`.
Constraints: Use exported `canonicalJson` from `change-waiver.ts` for reconciliation digests and byte limits. Semantic invocation identity excludes `sources`, is keyed by `toolCallId`, and compares timestamp strings byte-for-byte; parsed timestamps are used only for canonical sorting and eligibility. Persisted arrays must already equal their canonical order; validation never silently normalizes malformed evidence into a success-shaped value.
Requirements: REQ-WORKFLOW-RESUMED-SESSION-DURABILITY-001, REQ-WORKFLOW-RESUMED-SESSION-DURABILITY-002, REQ-WORKFLOW-RESUMED-SESSION-DURABILITY-004
ADRs: ADR-0041

## DES-WORKFLOW-RESUMED-SESSION-DURABILITY-002: Commutative ledger merge and persisting verification
Responsibilities: Refactor `verifyWorkflowChunks`/`verifyWorkflowLogFileUnlocked` in `packages/analysis/src/workflow.ts` into a pure next-state planner and a writer-lock-owned persister shared by both public persisting entry points. `verifyWorkflowLog` and `verifyWorkflowLogFile` accept optional persisting options with no synthetic compatible default, load `config.workflow`, and resolve run mode separately from ledger mode. Run mode controls lifecycle, multi-file rules, and each new source's mode; ledger mode is strict-sticky across ordinary merges. Only configured `expectedSessionId` persists in reconciliation, while per-run session IDs validate the strict transcript and remain source provenance. A configured anchor populates an absent persisted anchor as monotonic tightening; a present persisted anchor remains sticky when config later omits it. Explicit compatible weakening, disagreement between different present configured/persisted anchors, and supplied skew disagreement throw errors containing `WORKFLOW_RECONCILIATION_CONFIG_MISMATCH` before writes; reset without confirmation throws `WORKFLOW_RECONCILIATION_RESET_CONFIRMATION_REQUIRED`. Convert each successful current-run invocation into a provenance-bearing ledger entry; merge new identities, union distinct sorted sources, promote `incomplete` to a consistent terminal state, and treat a later consistent incomplete presentation of a terminal identity as a semantic no-op. Reject every other identity conflict with `WORKFLOW_INVOCATION_CONFLICT`. Preserve current-run `verification.invocations` only as the transcript projection while reconciliation becomes the cross-run authority. Add reset to both APIs and CLI; reset validates events/input, discards prior reconciliation, and rebuilds without mutating declarations. Return `WorkflowVerificationResult = { workflow: WorkflowManifest; warnings: WorkflowVerificationWarning[] }`; CLI JSON includes both fields, human output writes warning codes to stderr, and only `workflow` is persisted. Migration write failure throws after the workflow commit, while unsafe migration returns a successful warning.
Interfaces: `PersistingWorkflowVerificationOptions = Partial<WorkflowVerificationOptions> & { resetLedger?: boolean; confirmReset?: boolean }`, preserving existing `expectedSessionId`, age/future-skew, and byte/line limits; `WorkflowVerificationWarning = { code: "WORKFLOW_WAIVER_MIGRATION_SKIPPED"; message: string }`; `WorkflowVerificationResult = { workflow: WorkflowManifest; warnings: WorkflowVerificationWarning[] }`; `verifyWorkflowLog(root, logText, options?)`; `verifyWorkflowLogFile(root, paths, options?)`; CLI `workflow-verify <log...> [--reset-ledger --confirm]`; internal `planWorkflowReconciliation(current, runEvidence, resolvedRun, resetLedger)`.
Constraints: Update every persisting caller to consume `.workflow`; config validation keeps `expectedSessionId` strict-only. callers that deliberately request compatible mode do so only under compatible config. The internal non-persisting `verifyWorkflowLogFileUnlocked(..., persist=false)` path keeps returning `WorkflowManifest`, calls the same parser/lifecycle validator, and never plans migration or writes evidence. Compatible cross-file duplicate rejection remains scoped to the same `toolCallId` appearing in different supplied files. A failed config/conflict/limit/confirmation/transcript check preserves both evidence files; a second-file migration write failure is the sole nonzero path allowed after workflow commit.
Depends-On: DES-WORKFLOW-RESUMED-SESSION-DURABILITY-001
Requirements: REQ-WORKFLOW-RESUMED-SESSION-DURABILITY-001, REQ-WORKFLOW-MULTI-SESSION-001
ADRs: ADR-0010, ADR-0041

## DES-WORKFLOW-RESUMED-SESSION-DURABILITY-003: Deterministic bindings and fail-closed read-side validation
Responsibilities: Build an explicit immutable `WorkflowReconciliationPass` once per read or migration state, containing the canonical ledger, per-skill candidate indexes, freshly recomputed bindings, `headByEventIndex`, and optional instrumentation. Binding and waiver consumers share that pass; a distinct pass is created for an in-memory next workflow during migration. Filter candidates by `invokedAt <= recordedAt + reconciliation.skewMs`; in strict ledger mode apply strict-source and persisted configured-session filtering before reason classification. Process completed declarations in event order with one global previous-ledger-index floor. On gate/status/waiver reads, compare persisted bindings only when verification is present, event-current, and config-compatible. Emit global malformed/limit/config diagnostics and retain unverified/stale precedence. `runGate` passes resolved config; status and waiver surfaces load it normally.
Interfaces: `createWorkflowReconciliationPass(workflow, instrumentation?): WorkflowReconciliationPass` requires a validated reconciliation and throws `Workflow reconciliation is required for a reconciliation pass.` for absent or present-invalid input before indexing it; `computeWorkflowBindings(pass)`; `validateWorkflow(root, verificationOptions?, reconciliationConfig?)` loads `config.workflow` when the config argument is omitted and passes it separately as read-side config; `validateLoadedWorkflow(root, workflow, verificationOptions, reconciliationConfig, preloadedWaiverEvidence?, instrumentation?)` requires a resolved non-optional `WorkflowConfig`, creates at most one pass, and supplies it to both phases; pure `computeRawWorkflowDiagnostics(workflow, verificationOptions, reconciliationConfig, pass?)` requires resolved config on every read-side call; optional `WorkflowReconciliationInstrumentation`.
Constraints: `runGate` calls `validateWorkflow(root, config.workflow, config.workflow)`; `projectStatus`, `activeWorkflowWaivers`, and `workflowWaiverEvidenceDiagnostics` call the config-loading wrapper; single/bulk commands call `validateLoadedWorkflow(root, workflow, config.workflow, config.workflow, loaded)`. Omitting read-side config is forbidden below the wrapper. Config mismatch is asymmetric: stronger persisted strict evidence is accepted by compatible config; configured strict cannot accept persisted compatible evidence; a configured session constraint mismatches a different present persisted constraint on both reads and writes, while an absent persisted constraint is a write-side tightening opportunity but a read-side mismatch until persisted; configured skew must equal persisted skew. Invalid/over-limit/config-mismatched reconciliation suppresses all per-scope behavior. Writer-path merge/reset limit failures throw `WORKFLOW_RECONCILIATION_LIMIT`; load-side limit remains the global diagnostic. The existing tool-call duplicate scan stays current-run-only. Backward cross-session clocks may produce `WORKFLOW_INVOCATION_ORDER`. None of the global diagnostics is waivable.
Depends-On: DES-WORKFLOW-RESUMED-SESSION-DURABILITY-001
Requirements: REQ-WORKFLOW-RESUMED-SESSION-DURABILITY-002, REQ-WORKFLOW-RESUMED-SESSION-DURABILITY-004, REQ-WORKFLOW-EVIDENCE-WAIVER-012, REQ-WORKFLOW-WAIVER-BULK-002
ADRs: ADR-0041

## DES-WORKFLOW-RESUMED-SESSION-DURABILITY-004: Scope-local waiver snapshots and version compatibility
Responsibilities: In `workflow-waiver.ts`, keep snapshot version 1 for workflows without reconciliation and introduce snapshot version 2 for valid reconciliation. Preserve exported two-argument `workflowScopeEvidenceHead(workflow, eventIndex)` as a convenience wrapper that creates a one-call pass, while validation/migration use internal `workflowScopeEvidenceHeadForPass(pass, eventIndex)` so one pass serves all records. Both entry points require validated reconciliation and throw `Workflow reconciliation is required for a reconciliation pass.` before indexing when it is absent or present-invalid. Build the exact version-2 payload and resolve event index once. Define one pending predicate for read/write states. Replace the binary stale predicate with `waiverSnapshotState(context, index): "suppressed" | "current" | "stale"`: unverified/global reconciliation errors are suppressed; pending v1 same-or-resolved and matching v2 are current; incompatible/nonmatching records are stale. Downgrade, duplicate rejection, active listing, and stale audit consume this state verbatim, with listing additionally requiring a currently raised matching reason.
Interfaces: exported `snapshotVersionFor(workflow)`; `resolveEventIndex(workflow, event)` over the event already selected by `resolveEvent`; `workflowScopeEvidenceHead(workflow, eventIndex)`; internal `workflowScopeEvidenceHeadForPass(pass, eventIndex)`; version-aware `snapshotPayload`/`snapshotHashFor`; exported `waiverSnapshotState`.
Constraints: Provenance sources, verification timestamps, and unrelated skills are excluded from the scope head. Suppressed contexts never compute `currentHash` or any snapshot payload. Present invalid reconciliation has no snapshot version and blocks both single and bulk recording. Existing version-1 records remain byte-identical.
Depends-On: DES-WORKFLOW-RESUMED-SESSION-DURABILITY-001, DES-WORKFLOW-RESUMED-SESSION-DURABILITY-003
Requirements: REQ-WORKFLOW-RESUMED-SESSION-DURABILITY-003, REQ-WORKFLOW-EVIDENCE-WAIVER-012, REQ-WORKFLOW-EVIDENCE-WAIVER-014, REQ-WORKFLOW-WAIVER-BULK-001, REQ-WORKFLOW-WAIVER-BULK-002
ADRs: ADR-0026, ADR-0041

## DES-WORKFLOW-RESUMED-SESSION-DURABILITY-005: Recoverable workflow-first waiver migration
Responsibilities: While holding the existing evidence writer lock, load workflow and waiver bytes once, validate and plan the next workflow document plus deterministic version-2 successor records in memory, then atomically replace `workflow.json` first and replace `workflow-waivers.json` second. Select every authoritative, validly linked version-1 scope whose next-state reason is unchanged or resolved, ignoring legacy global-head staleness per the approved rescue policy; preserve approval fields and original `waiverRecordedAt`, append in authoritative-record position order, set snapshot version 2, and hash each successor against the in-memory next workflow. Call pure `computeRawWorkflowDiagnostics(nextWorkflow, config.workflow, config.workflow, nextPass)` only after the in-memory next state is fully classified from that next state's persisted reconciliation values plus resolved `config.workflow` wherever read-side mismatch rules apply; raw per-run tightening options are not a separate input, but may affect snapshots through sticky values persisted into the next state; suppressed/unavailable diagnostics never mean resolved, and the previous state adds no migration predicate. Retry selection and append on every later successful persisting verification, including reset-ledger, until no pending scope remains.
Interfaces: internal `WorkflowWaiverMigrationPlan = { status: "none" } | { status: "planned"; successors: [WorkflowWaiverRecord, ...WorkflowWaiverRecord[]] } | { status: "skipped"; skipReason: string }`; `planWorkflowWaiverMigration(nextWorkflow, loadedWaivers, reconciliationConfig, nextPass): WorkflowWaiverMigrationPlan`, with no previous-workflow input because previous state must not enter the pending predicate; internal `commitWorkflowReconciliation(nextWorkflow, migrationPlan): WorkflowVerificationResult`, which performs no waiver write and emits no migration warning for `none`, writes the nonempty successors only for `planned`, and emits `WORKFLOW_WAIVER_MIGRATION_SKIPPED` with `skipReason` for `skipped`. Zero pending scopes always produce `none`, never `planned`.
Constraints: All planning precedes writes. A workflow write failure changes neither file. A waiver write failure may leave only the safe next workflow; it throws an error containing `WORKFLOW_WAIVER_MIGRATION_WRITE_FAILED` so CLI exits nonzero, reports migration pending, and is idempotently recoverable because selection is recomputed from authoritative linked v1 records rather than an anchor. Invalid document/top-level shape, record field shape/type including allow-listed code, or sequence/hash-chain data prevents append but not workflow replacement; the successful command result and stderr carry non-persisted warning `WORKFLOW_WAIVER_MIGRATION_SKIPPED`. Only after those whole-file checks pass may declaration/scope linkage failure exclude one record. Migration is system-initiated and bypasses human recording preconditions without altering historical records.
Depends-On: DES-WORKFLOW-RESUMED-SESSION-DURABILITY-002, DES-WORKFLOW-RESUMED-SESSION-DURABILITY-004
Requirements: REQ-WORKFLOW-RESUMED-SESSION-DURABILITY-005
ADRs: ADR-0041

## DES-WORKFLOW-RESUMED-SESSION-DURABILITY-006: Attestation projection
Responsibilities: Update `workflowEvidenceHead` so legacy documents without a `reconciliation` own property retain the exact old digest using the existing module-private canonicalizer. Select this branch by own-property presence, never truthiness or nullish equality. For reconciliation-bearing documents, import exported `canonicalJson` from `change-waiver.ts` and hash `canonicalJson({ verification, reconciliation })`: embed the existing full projection, the legacy-short `{ eventsSha256, sourceSha256 }` object, or `null`; embed only reconciliation schema/mode/session/skew and ledger/binding digests. For any present malformed reconciliation value, including null, array, primitive, or object, project the five required keys with explicit `null` for missing/wrong-typed values and include `expectedSessionId` only when it is a string, allowing attestation collection to complete while validation remains fail-closed. Keep reconciliation attested after `recordWorkflow` clears verification. Update `README.md` evidence-head documentation.
Interfaces: `workflowEvidenceHead(workflow): string | null` (signature unchanged).
Constraints: Never include full invocation/binding arrays in the attestation projection; their validated digests are authoritative. `recordWorkflow` preserves any present reconciliation property byte-for-byte, including malformed values, so declaration recording cannot silently re-enter legacy behavior. All malformed reconciliation variants intentionally collapse to the same required-five-null projection (plus a valid optional session string when available); fail-closed diagnostics, not the attestation head, distinguish malformed forms. Legacy digest compatibility is byte-for-byte.
Depends-On: DES-WORKFLOW-RESUMED-SESSION-DURABILITY-001
Requirements: REQ-WORKFLOW-RESUMED-SESSION-DURABILITY-006, REQ-ATTESTATION-EVIDENCE-STABILITY-004
ADRs: ADR-0041

## DES-WORKFLOW-RESUMED-SESSION-DURABILITY-007: CLI, documentation, and regression coverage
Responsibilities: Wire run mode/session/skew and reset confirmation in `packages/cli/src/main.ts`; configured strict mode, `--strict`, or `--session-id` can only tighten run mode, per-run session IDs remain provenance, and no API option weakens strict config. Make single and bulk waiver recording reject malformed, limit, and config-mismatch diagnostics; document compatible live-session verification versus configured-strict next-session terminal verification, reset, limits, conflicts, global diagnostics, automatic version-1-to-version-2 migration and its valid-linkage/same-or-resolved trust criterion, migration skipped/write failure plus the repair-then-persisting-verify retry loop, sticky ledger mode/configured-session behavior, monotonic distinct-source growth, bulk blockers, which config mismatches persisting verification repairs versus which state changes require confirmed reset, and the suppressing mismatch then post-verification waiver-staleness sequence for `maxEventSkewMs` changes. Add focused tests in the existing required command buckets for merge/order, strict provenance across distinct sessions, API result/caller migration, exact pre-write codes, tri-state waiver behavior, explicit pass instrumentation, reset, migration/retry, suppression, and attestation. No separate command bucket is added because these existing required commands directly own every changed surface.
Interfaces: Existing commands plus `workflow-verify <log...> --reset-ledger --confirm`; no new service/runtime.
Constraints: Test names carry explicit `TEST-*` IDs and `@verifies` links. Tests must assert exact diagnostic/error codes and byte preservation on every rejected write.
Depends-On: DES-WORKFLOW-RESUMED-SESSION-DURABILITY-002, DES-WORKFLOW-RESUMED-SESSION-DURABILITY-003, DES-WORKFLOW-RESUMED-SESSION-DURABILITY-004, DES-WORKFLOW-RESUMED-SESSION-DURABILITY-005, DES-WORKFLOW-RESUMED-SESSION-DURABILITY-006
