# npm audit remediation design

## DES-NPM-AUDIT-REMEDIATION-001: Advisory assessment and deterministic evidence checker
Responsibilities: Preserve the reviewed GHSA-82fw-gwwq-j7x9 assessment in CHANGE-0022; deterministically verify the advisory identity, two affected dependency paths, vulnerable and fixed ranges, exploit preconditions, current reachability, no-3.x-fix rationale, Node.js development constraint, and recorded time-bound zero-finding npm audit result without querying the network during ordinary tests.
Interfaces: `.musubix/changes/CHANGE-0022.md` is the normative assessment and verification record; `scripts/check-npm-audit-remediation.mjs evidence` reads that file and emits one JSON object `{ valid: boolean, diagnostics: Array<{ code, message, path? }> }`; `NPM_AUDIT_REMEDIATION_CHANGE_PATH` overrides the change path for isolated fixtures; `tests/npm-audit-remediation.test.ts` invokes the checker through Node.js, asserts the repository succeeds, and uses separate temporary change fixtures for missing advisory identity, incomplete reachability, missing no-3.x-fix rationale, nonzero info/low/moderate/high/critical/total counts, malformed or future timestamps, and missing or mismatched lockfile digests.
Constraints: The checker requires GHSA-82fw-gwwq-j7x9, CVE-2026-84373, CVSS 5.9, CWE-22, direct `vitest`, transitive `@vitest/mocker`, affected range `>=2.1.0 <4.1.11`, fixed version 4.1.11, development-only classification, absent current browser/plugin/network exposure, and the lack of a maintained 3.x fix; it requires recorded info, low, moderate, high, critical, and total counts all equal zero; it validates a calendrically valid RFC 3339 UTC `Z` timestamp no more than five minutes in the future and a lowercase hexadecimal digest equal to the current lockfile file-byte SHA-256, but never executes `npm audit`; recurring freshness comes from the weekly workflow so deterministic tests do not expire solely with wall-clock age; the verification-time network command is run separately at the root workspace with development dependencies and all severities included, and its summary is copied into CHANGE-0022; every invalid or incomplete fixture fails closed with a diagnostic identifying the missing evidence class.
Requirements: REQ-NPM-AUDIT-REMEDIATION-001 REQ-NPM-AUDIT-REMEDIATION-002
ADRs: ADR-0036

## DES-NPM-AUDIT-REMEDIATION-002: Fixed Vitest dependency graph and compatibility contract
Responsibilities: Upgrade the direct Vitest constraint to the minimum stable fixed 4.x line; regenerate the npm lockfile through npm; verify every root dependency path for `vitest` and `@vitest/mocker` resolves outside the advisory range; preserve Vitest selection, timeout, and worker constraints; prove that production dependency and package-distribution surfaces are unchanged.
Interfaces: `package.json` declares `devDependencies.vitest: "^4.1.11"` and is normative for the reviewed `exports` and `files` surfaces; `package-lock.json` supplies root package metadata and all installed package records; `vitest.config.ts` supplies `include`, `testTimeout`, and `maxWorkers`; `.github/workflows/ci.yml` supplies the Node.js lines and focused test commands used in CI; `package.json` scripts supply normal, adapter, watch, and audit-report entry points; `scripts/check-npm-audit-remediation.mjs lock` verifies the manifest, lockfile, CI Node/Vite/Vitest engine constraints, scripts, and configuration text without loading Vitest or using the registry; `NPM_AUDIT_REMEDIATION_ROOT` overrides the repository root for isolated fixtures; `tests/npm-audit-remediation.test.ts` uses separate temporary fixtures for wrong lockfile version, a legacy dependency map, missing Vitest/mocker/Vite package records, vulnerable root and nested records, non-development records, direct mocker promotion, override presence, divergent Vitest/mocker versions, malformed or prerelease versions, an out-of-range major, exact Vitest/Vite engine drift, drifted CI Node lines or commands, job-level failure suppression, incompatible manifest/config/scripts, and removed Vitest configuration options.
Constraints: The checker requires `lockfileVersion: 3`, requires a `packages` object, rejects a legacy top-level `dependencies` map, enumerates records where `key === "node_modules/vitest" || key.endsWith("/node_modules/vitest")` and where `key === "node_modules/@vitest/mocker" || key.endsWith("/node_modules/@vitest/mocker")`, and uses package path rather than an optional record `name` field so npm alias records are outside this change's scope; it fails when either package has no matching record; every matched record must be development-only and have a stable numeric `major.minor.patch` version with no prerelease, compared as a numeric tuple and constrained to `>=4.1.11 <5.0.0`, and resolved Vitest/mocker version sets remain aligned; `@vitest/mocker` remains absent from direct `devDependencies`, and `overrides`/patched forks remain absent; root-lock `dependencies`, `devDependencies`, `bin`, `engines`, and `workspaces` remain aligned with the manifest, while `exports` and `files` are pinned to the reviewed literal package surface in the checker; the checker parses `.github/workflows/ci.yml` and requires `core-portability` to execute the full test command on Node.js 22, `node-compatibility` to execute it on Node.js 20 and 24, and the Node.js 24 `native-adapters` and `formal-solvers` jobs to execute their focused Vitest commands without job-level failure suppression; the published package keeps `engines.node: ">=20"`; resolved Vitest engines must equal `^20.0.0 || ^22.0.0 || >=24.0.0`, and every Vite record must remain stable `>=8.3.0 <9.0.0` with exact engine string `^20.19.0 || >=22.12.0`; `@vitest/mocker` has no independent engine assertion; `tests/**/*.test.ts`, 20-second timeout, global two-worker cap, and adapter one-worker cap remain effective; the reviewed Vitest 4 migration surface includes changed `vi.restoreAllMocks`/`restoreMocks` behavior, mock names, invocation order, automock behavior, Module Runner replacement, pool rework, and removed deprecated options; the repository does not use `restoreAllMocks`, `restoreMocks`, `getMockName`, `invocationCallOrder`, custom environments, custom pools/reporters, browser mode, coverage, or removed configuration, and existing `vi.spyOn` uses restore each spy explicitly; `vi.mock` compatibility is proven by the complete test suite; the checker rejects removed configuration keys used by this repository's config surface: `poolOptions`, `singleThread`, `singleFork`, `maxThreads`, `maxForks`, `minWorkers`, `poolMatchGlobs`, `environmentMatchGlobs`, top-level `test.deps.external`, `test.deps.inline`, `test.deps.fallbackCJS`, `workspace`, `threads.useAtomics`, `browser.testerScripts`, and reporter `basic`.
Requirements: REQ-NPM-AUDIT-REMEDIATION-002 REQ-NPM-AUDIT-REMEDIATION-003
ADRs: ADR-0036
Depends-On: DES-NPM-AUDIT-REMEDIATION-001

## DES-NPM-AUDIT-REMEDIATION-003: Dependency-audit monitoring guidance
Responsibilities: Document the dependency-audit review workflow in English and Japanese; distinguish reachability assessment from remediation; require explicit residual-risk and monitoring evidence when no maintained safe fix is applied; schedule and expose manual execution of the full audit report; verify the documents and workflow stay aligned.
Interfaces: `README.md`; `README-ja.md`; `package.json` defines `audit:report` as exact root-workspace `npm audit --json`; `.github/workflows/dependency-audit.yml` runs `npm run audit:report`; `scripts/github-actions-lock.json` supplies the reviewed immutable action SHAs; `scripts/check-github-actions.mjs` includes the dependency-audit workflow in per-reference lock validation while retaining historical drift baselines for the original release workflows; `scripts/check-npm-audit-remediation.mjs` checks the exact script definition, stable document anchors, exact weekly schedule, manual trigger, Node.js 24 setup, immutable checkout/setup-node references, full report command, and unsuppressed command failure; `NPM_AUDIT_REMEDIATION_ROOT` overrides document and workflow paths for isolated fixtures; `tests/npm-audit-remediation.test.ts` independently degrades both documents and every script/workflow contract.
Constraints: Guidance requires a root-workspace `npm audit --json` run that includes development dependencies and all severities when a finding is reported; each finding records advisory ID, dependency path, production/build/test reachability, fixed-version availability, remediation decision, and remaining monitoring obligation; development-only or currently unreachable code is not treated as remediated when a maintained compatible fix is available; the documentation does not promise that a previously clean audit remains clean indefinitely; the workflow uses exact cron `23 4 * * 1`, supports `workflow_dispatch`, runs Node.js 24, pins official actions by immutable reviewed SHA, contains exactly one byte-exact `run: npm run audit:report` step with no redirection, filtering, shell override, or `continue-on-error` key, and has no job-level `continue-on-error` key, so npm audit's nonzero finding result fails the job and its JSON stays in the GitHub Actions run log; `scripts/check-github-actions.mjs` owns per-reference action-lock validation for this workflow, while `scripts/check-npm-audit-remediation.mjs` exclusively owns its trigger, command, Node.js, and failure-propagation policy because the new workflow is deliberately outside CHANGE-0021's historical behavior baseline and runner-job contract; English and Japanese policy checks fail independently and identify the incomplete document.
Requirements: REQ-NPM-AUDIT-REMEDIATION-004
ADRs: ADR-0036
Depends-On: DES-NPM-AUDIT-REMEDIATION-002
